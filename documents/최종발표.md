## 권장 확인 순서

발표를 처음 보는 사람은 다음 순서가 가장 빠르다.

1. [최종 발표 덱](final/ppt/slides/index.html)으로 프로젝트의 문제·해법·증거를 먼저 본다.
2. [최종 프로젝트 한눈에](facts/최종프로젝트.md)에서 구현 범위와 수치를 확인한다.
3. [최종 시스템 구조](최종시스템.md)와 [실제 하루](실제하루.md)에서 시스템 계보를 읽는다.
4. 발표 직전에는 HTML 덱의 `발표 요약`과 `Q&A` 백업 슬라이드를 확인한다.

## 발표 자료 사용법

발표 관련 내용은 최종 HTML 하나에 모았다. 별도 대본이나 Q&A 파일을 열지 않는다.

| 조작 | 동작 |
|---|---|
| `←` `→` / `Space` | 슬라이드 이동 |
| `F` | 전체화면 |
| `Home` | 첫 화면 |
| `End` | 감사·Q&A 화면 |
| Q&A 화면에서 `→` | 발표 요약·범위/설계·숫자/검증 백업으로 이동 |

!!! info "발표자용 요약과 Q&A"
    화면별 핵심 멘트는 덱 내부의 `data-notes`에 짧게 남겨두었고, 발표 흐름·역할·핵심 수치와
    예상 질문 답변은 덱 마지막 백업 슬라이드에 통합했다. 본편 진행에는 포함하지 않는다.

!!! info "자료의 우선순위"
    `slides/index.html`이 발표용 정본이다. `quantinue-final.pdf`는 인쇄·공유용 고정본이다.
    1차 발표자료는 [MVP 1차 아카이브](facts/MVP1차.md) 안에서 이전 단계의 근거로만 보존한다.

## 이 위키에서의 프로젝트 명칭

최종 결과를 설명할 때는 `MVP-2` 대신 **최종 프로젝트**라고 부른다. `MVP 1차`는
문제 발견과 구현 토대를 만든 이전 단계이므로, 사이드바 하단의 접힌 아카이브에서만
필요할 때 열어본다. `quantinue-v2`는 소스 디렉터리명으로만 남는다.

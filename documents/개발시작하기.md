## 가장 빠른 안전 실행

외부 API·DB·LLM 없이 deterministic fixture로 웹만 띄우는 경로다.

```bash
cd /Users/sunghyuk/Documents/ClaudeCode/quantinue-v2/app-v2
cp .env.example .env
uv sync
uv run uvicorn quantinue.main:app --reload --port 8000
```

브라우저에서 `http://127.0.0.1:8000`을 연다. 이 모드는 `fixture + memory + mock LLM +
mock broker` 조합이므로 외부 키나 네트워크가 필요하지 않다. `/`는 세션에 따라
`/admin` 또는 `/me`로 이동한다.

## PostgreSQL을 포함한 개발 실행

```bash
cd /Users/sunghyuk/Documents/ClaudeCode/quantinue-v2/app-v2
docker compose up --build --wait
```

현재 `compose.yaml`의 계약은 다음과 같다.

| 대상 | 주소 | 의미 |
|---|---|---|
| PostgreSQL 호스트 접근 | `127.0.0.1:5445` | Quantinue 전용 DB; 호스트 `5432`를 건드리지 않는다. |
| PostgreSQL 컨테이너 접근 | `db:5432` | web 컨테이너 내부 DNS 주소 |
| Compose 웹 | `http://127.0.0.1:8011` | Docker web 서비스 |
| DB 초기화 | `db/schema.sql` | 최초 named volume 생성 시 자동 적용 |

`docker compose down`은 컨테이너만 내리고 named volume은 보존한다. 데이터를 지울
의도가 없다면 `-v`를 붙이지 않는다.

!!! warning "포트 문서 충돌"
    최종 `compose.yaml`은 PostgreSQL `5445`를 사용하지만 일부 오래된 `.env.example`
    주석과 설계 추적표에는 `5444`가 남아 있다. **현재 실행 기준은 compose.yaml과
    운영 가이드의 5445**다. 이 불일치를 해결하는 수정은 다음 애플리케이션 저장소
    정리 작업으로 남겨야 한다.

## 운영 관측 실행

운영 관측은 개발 서버와 별개다. 운영 JOB과 WatchRunner의 소유권을 한 프로세스만
갖도록 하는 실행기를 사용한다.

```bash
cd /Users/sunghyuk/Documents/ClaudeCode/quantinue-v2/app-v2
docker start app-v2-db-1
./scripts/run_observation.sh
```

기본 관측 포트는 `8020`, 로그는 `observation.log`, 단일 소유권 잠금은
`.runtime/observation-owner.lock`이다. 코드를 고칠 때 이 프로세스에 `--reload`를
붙이거나 두 번째 관측 프로세스를 띄우지 않는다. 개발용 앱은 8000 또는 별도 포트,
운영 관측은 8020으로 분리한다.

## 설정 모드

| 목적 | `DATA_MODE` | `DATABASE_MODE` | `LLM_MODE` | `BROKER_MODE` | 부작용 |
|---|---|---|---|---|---|
| 기본 단위 개발 | `fixture` | `memory` | `mock` | `mock` | 없음 |
| 공개 데이터 확인 | `public` | `memory` 또는 `postgres` | `mock` 또는 `local` | `mock` | 공개 HTTP 호출 |
| 로컬 모델 확인 | `fixture` 또는 `public` | `memory` 또는 `postgres` | `local` | `mock` | 로컬 LLM 필요 |
| 운영 관측 | `public` | `postgres` | `openai` 또는 명시한 모드 | `mock` | 외부 데이터·LLM 비용 가능 |
| Paper opt-in | `public` | `postgres` | 명시한 모드 | `alpaca` | Paper 주문·상태 변경 가능 |

실계좌·live endpoint는 허용하지 않는다. `QUANTINUE_TRADING_ENABLED=true`는
`BROKER_MODE=alpaca`와 함께 사용할 때만 paper 주문 경로를 연다. 기본값은 항상
`false`다. 비밀값은 `.env` 또는 secret manager에만 두고 문서·로그·스크린샷에 남기지 않는다.

기본 실행에 포함되지 않는 opt-in 영역이다.

## 첫 수정 과제의 흐름

1. 이 페이지와 [코드맵](코드맵.md), [데이터 사전](데이터사전.md)을 읽는다.
2. 관련 역할의 입력·출력 계약을 [역할·협업 계약](역할협업계약.md)에서 확인한다.
3. `tests/unit/`에서 가장 가까운 기존 테스트를 찾고 실패 케이스부터 읽는다.
4. 구현·단위 테스트·필요한 통합 테스트를 함께 수정한다.
5. `schema.sql`, `pipeline.yaml`, API 응답, 운영 상태 중 하나가 바뀌면 이 위키의
   [데이터 모델](데이터모델.md), [설정·정책](설정정책.md), [API 계약](API계약.md)도 갱신한다.
6. 전체 검증 명령과 `git diff`를 확인하고 결정·운영 영향이 있으면 [결정 로그](facts/결정로그.md)에 남긴다.

## 막혔을 때 확인 순서

| 증상 | 먼저 볼 곳 | 판단 |
|---|---|---|
| 앱이 안 뜸 | `.env`, `src/quantinue/core/config.py`, 기동 로그 | 설정 검증 또는 포트 문제 |
| DB 연결 실패 | `compose.yaml`, `QUANTINUE_DATABASE_URL`, `docker compose ps` | 호스트는 5445, 컨테이너는 `db:5432` |
| JOB이 안 돎 | `/schedule`, `/api/runtime/status`, `tb_job_run` | web-only인지 owner가 붙었는지 확인 |
| 같은 주문이 반복됨 | `tb_order`, `order_submissions`, idempotency key | broker 재호출 전에 원장 소유권 확인 |
| LLM 비용이 이상함 | `tb_llm_usage`, `tb_llm_budget_reservation`, `pipeline.yaml` | 모델 요율·예약·정산을 함께 확인 |
| 화면과 원장이 다름 | `src/quantinue/api/`, 해당 DB read 모델, 관련 테스트 | 화면을 고치기 전에 원장 값을 기준으로 확인 |

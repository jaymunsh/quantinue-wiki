# 📘 최종 프로젝트 운영 가이드

!!! warning "운영 전제"
    이 페이지는 현재 로컬 운영의 빠른 진입점이다. 실제 기동·장애 대응의 전체 절차는
    이 위키의 [통합 설계서](final/quantinue-integrated-design.html)와
    [pipeline.yaml 원문](final/reference/pipeline.yaml)을 기준으로 한다.

## 빠른 확인

| 대상 | 기준 |
|---|---|
| 운영 앱 | `127.0.0.1:8020` |
| 개발용 web-only | `127.0.0.1:8021` |
| 운영 DB | `127.0.0.1:5445` |
| 브로커 | `mock` |
| 현재 운영 스위치 | `watch=true` · `rejudge=false` · `stream=false` |
| 관리자 화면 | `http://127.0.0.1:8020/admin` |

## 켜기

```bash
cd <PROJECT_ROOT>/app-v2
docker start app-v2-db-1
./scripts/run_observation.sh
```

운영 인스턴스는 하나만 실행한다. `run_observation.sh`가 작업 owner와 백그라운드 JOB·
WatchRunner를 함께 소유한다. 개발 화면을 확인할 때는 운영 runner를 중복 기동하지 않는다.

## 확인 순서

1. `/health`에서 앱·브로커·LLM 모드를 확인한다.
2. `/admin`에서 JOB 체인의 실패·굳은 슬롯·계좌·LLM 비용을 확인한다.
3. 정규장에는 1분 방어선과 최근 WatchRunner tick을 확인한다.
4. 평일 일일 요약 Telegram이 도착했는지 확인한다.
5. 문제가 있으면 `observation.log`와 원장 상태를 함께 본다.

## 끄기

```bash
pkill -f "uvicorn quantinue.main:app"
```

JOB이 실행 중일 때 중단하면 슬롯이 `running`으로 남을 수 있다. 종료 전 관제실에서 실행 중
JOB이 없는지 확인하고, 필요하면 관제실의 잠금 해제 절차를 따른다.

## 운영 활성화 순서

현재 개발 완료 범위와 실제 활성화 범위를 분리한다.

1. `watch=true` poll-only 정규장 관측
2. clean 일일 슬롯과 비용·retry·알림 대조
3. `rejudge=true` Gate B 기능일·다음 거래일 검증
4. `stream=true` 웹소켓 연결·복구·폴링 fallback 검증

토큰·API 키·heartbeat URL은 문서·로그·스크린샷에 남기지 않는다.

# 🗓️ 실제 하루로 보는 Quantinue

!!! success "최종 프로젝트 실측 서사 · 2026-07-21"
    설계 설명보다 먼저, 실제 거래일 하루를 따라가며 시스템의 입력·판단·체결·회고가
    어떻게 연결되는지 보는 페이지다. 수치는 `quantinue-day-anatomy.html`의 실측을 기준으로 한다.

## 하루의 흐름

| 시점 | 시스템이 한 일 | 사람의 개입 |
|---|---|---|
| 슬롯 시작 | 뉴욕 거래일 기준으로 due JOB을 확인하고 원장에 예약 | 없음 |
| 데이터 수집 | 유니버스·일봉·공시·뉴스·와이어·거시 데이터를 PostgreSQL에 저장 | 없음 |
| 후보 선정 | DB에 저장된 일봉을 랭킹해 오늘의 픽을 선정 | 없음 |
| 내부자 신호 | Form 4를 결정론 규칙으로 채점 | 없음 |
| 전략 판단 | 공격형·안전형 Strategist가 제안하고 Critic이 반박 | 없음 |
| 실행 | 청산을 먼저 처리하고, 승인된 후보만 계좌 한도 안에서 MockBroker로 체결 | 없음 |
| 장중 | 1분마다 손절·익절선을 확인하고 필요하면 모의 청산 | 없음 |
| 알림 | 슬롯 결과와 실패를 Telegram으로 요약 | 없음 |

## 실제 관측 사례

07-21 하루에는 다음과 같은 흐름이 기록됐다.

- 일봉 데이터가 약 1,940종목에 대해 원장에 저장됐다.
- DB 랭킹으로 당일 픽 22종목을 선정했다(추세 주도주 14·52주 신고가 7·눌림목 1).
- 장중 방어선이 TMO를 기간 청산했다.
- 화면·알림은 별도 판단을 만들지 않고 PostgreSQL 원장을 읽었다.

## 확인된 범위

- 후보 선정부터 주문·체결까지의 계보가 끊기지 않는다.
- `why buy`뿐 아니라 `why not buy`도 보류·기각 사유로 남는다.
- 손절·익절은 LLM의 기분이 아니라 매수 시점에 저장한 규칙으로 방어한다.
- JOB 하나가 실패해도 실패 위치와 원장 상태를 분리해 확인할 수 있다.

## 확인되지 않은 범위

이 페이지는 수익률을 보장하는 성과 보고서가 아니다. 재현 가능한 실행 계보와 안전장치가
실제로 작동했는지를 보여주는 관측 기록이다. 전체 집계는 [운영 검증과 한계](운영검증.md)에서 본다.
